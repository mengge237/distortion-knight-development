# 代码约定

## 单例规范

项目中有 **9 个管理器** 使用单例模式，必须在 `Awake` 中处理重复实例：

```csharp
public static ManagerName Instance { get; private set; }

private void Awake()
{
    if (Instance == null)
    {
        Instance = this;
    }
    else
    {
        Destroy(gameObject);
    }
}
```

### 单例管理器清单

| 管理器 | 命名空间 | Awake 行为 | OnDestroy 行为 |
|--------|----------|------------|----------------|
| `BattleManager` | MutationChess.Battle | 标准（赋值或销毁） | 无 |
| `TurnManager` | MutationChess.Battle | 标准 | 无 |
| `HandManager` | MutationChess.UI | 标准 | 无 |
| `BattleLogManager` | MutationChess.UI | 标准 | 无 |
| `UILayoutManager` | MutationChess.UI | 标准（带 [ExecuteAlways]） | 无 |
| `StatusBarManager` | MutationChess.UI | 标准 | 无 |
| `SettingsManager` | MutationChess.Core | 标准 | 置 null |
| `MapManager` | MutationChess.Map | 标准 | 无 |
| `PlayerDataManager` | MutationChess.Core | 懒加载 FindObjectOfType | 无（不使用 DontDestroyOnLoad） |

### 注意事项

- `PlayerDataManager` 使用懒加载 `FindObjectOfType` 而非标准 Awake 赋值，且**不调用 `DontDestroyOnLoad`**
- `UILayoutManager` 标记了 `[ExecuteAlways]`，在编辑器非播放模式下也会执行
- `SettingsManager` 在 `OnDestroy` 中将 `Instance` 置 null，确保场景切换后安全

## 命名规范

### C# 命名

| 类型 | 规范 | 示例 |
|------|------|------|
| 类名 | PascalCase | `BattleManager`, `CardEffect` |
| 方法名 | PascalCase | `StartBattle()`, `DrawCards()` |
| 属性名 | PascalCase | `IsInBattle`, `CurrentEnemy` |
| 公共字段 | PascalCase | `maxEnergy`, `cardsPerTurn`（当前为 camelCase，历史遗留） |
| 私有字段 | camelCase | `isInBattle`, `currentEnemy` |
| 常量 | PascalCase | `MaxHandSize` |
| 事件 | PascalCase + On 前缀 | `OnBattleEnd`, `OnPlayerTurnStart` |
| 枚举值 | PascalCase | `NormalMonster`, `Attack` |
| 枚举名（中文） | 中文 PascalCase | `CardName.攻击`, `NodeType.商店` |

### Unity 命名

| 类型 | 规范 | 示例 |
|------|------|------|
| 预制体 | PascalCase | `CardPrefab`, `MapNode` |
| 场景 | PascalCase | `MainScene` |
| ScriptableObject | PascalCase | `DefaultMapConfig` |
| 文件夹 | PascalCase | `Battle/`, `Effects/`, `Map/` |

### 文件名与类名一致

每个 `.cs` 文件必须包含与其文件名完全匹配的公共类。

## 注释规范

### 保留的注释类型

- **Why 注释**：解释为什么这样做（非显而易见的设计决策）
- **XML 文档注释**：公共类和公共方法的 `/// <summary>` 文档

```csharp
/// <summary>
/// 获取或设置当前战斗中的敌人实例。
/// </summary>
public Enemy CurrentEnemy { get; private set; }

// 为什么使用 FindObjectOfType 而非 Awake 单例：
// PlayerDataManager 需要跨场景复用但不持久的特殊处理
```

### 禁止的注释类型

- **星号装饰注释**：禁止 `// **********`、`// ========` 等纯装饰性分割线
- **复述代码注释**：禁止 `// 设置伤害为 5` 这种对代码的简单复述
- **乱码注释**：所有 `????` 乱码必须删除
- **空块注释**：禁止 `{ } // TODO: 待实现` 而不创建对应 Issue 追踪

### 注释语言

- 代码注释统一使用 **中文**
- XML 文档注释可使用 **中文**
- 枚举值名称使用 **中文**

## 提交信息格式

遵循 Conventional Commits 规范：

```
<type>(<scope>): <description>

[可选正文]

[可选尾部]
```

### Type 列表

| Type | 说明 |
|------|------|
| `feat` | 新功能 |
| `fix` | 修复 Bug |
| `refactor` | 重构（不改变功能） |
| `docs` | 文档变更 |
| `style` | 代码格式（不影响逻辑） |
| `perf` | 性能优化 |
| `test` | 测试相关 |
| `chore` | 构建/工具/依赖变更 |

### Scope（可选）

建议使用系统名作为 scope：

```
feat(battle): 实现敌人 Boss 二阶段切换
fix(map): 修复负索引导致的数组越界
refactor(effects): 统一 CardEffect 子类命名
docs(wiki): 新增架构设计文档
```

### 示例

```
feat(battle): 实现战斗胜利后的奖励面板流程
fix(hand): 修复同引用卡牌重复添加到 handCards 的问题
refactor(core): 删除未使用的 upgradeDescription 字段
docs: 新增代码约定文档
```
